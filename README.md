# GEACX1: полный комплект восстановления JetPack 7.2

**Для GEACX1 / AGX Orin 32 ГБ / 510JX0 r3.0. Компьютер для запуска: Ubuntu 24.04, Intel или AMD.**

[**Скачать весь проект ZIP**](https://github.com/tehblok/geacx1-recovery-validation/archive/refs/heads/main.zip) · [**Инструкция с картинками — PDF**](docs/GEACX1-GUIDE-RU.pdf) · [Руководство производителя](docs/GEACX1-MANUFACTURER-MANUAL.pdf)

Репозиторий публичный: скачивание доступно без регистрации и входа в GitHub.
Можно пользоваться обычной кнопкой **Code → Download ZIP**. ZIP проекта содержит
все данные прошивки; дополнительные файлы с сайта производителя скачивать не нужно.
Точный размер и SHA-256 полного архива указаны в `parts.json`. Интернет на Ubuntu
потребуется для установки системных инструментов через APT.

## Запуск

1. Скачайте ZIP и распакуйте его **на Ubuntu** через «Извлечь сюда».
2. Откройте распакованную папку проекта, где лежит **START.sh**, в терминале.
3. Выполните одну команду:

```bash
bash START.sh
```

Запускайте от обычного пользователя. Основной мастер сам запросит пароль sudo.
Подготовка проверит части данных, соберёт исходный архив и проверит распакованные
файлы. По умолчанию комплект появится в **~/geacx1-kit-v1.4**. Затем откроется мастер.

В мастере выберите **1 — восстановление с нуля**, затем eMMC, NVMe или оба накопителя.
Этот сценарий рассчитан на не загружающуюся плату: рабочая старая Ubuntu не нужна.
Запись на выбранный накопитель начинается только после отдельного подтверждения.

Рабочий диск компьютера — **ext4**. Желательно иметь **100–120 ГиБ свободно** для
одного накопителя, около **180 ГиБ для обоих**. После распаковки комплекта для
подготовки прошивки должно оставаться не менее **80 ГиБ**.

Если комплект уже распакован, для повторного запуска используйте:

```bash
bash "$HOME/geacx1-kit-v1.4/geacx1-recovery/START.sh"
```

Начальный скрипт намеренно не перезаписывает существующую папку. Для v1.4 заново
скачайте проект и запустите корневой `START.sh`; старую рабочую папку v1.2/v1.3 не
используйте для новой прошивки. Для новой копии можно указать другую папку на ext4:
`bash START.sh --destination /путь/новая-папка`.

## USB и медленный кабель

Мастер показывает согласованную скорость USB, сообщает о хабе в цепочке и перед
операцией 3 секунды проверяет, что плата остаётся подключённой в Recovery.
480 Мбит/с — скорость соединения USB 2.0, не фактическая скорость записи.
Эта проверка не передаёт тестовый образ на плату и не гарантирует качество кабеля.
При отключении или переподключении до запуска операция отменяется.

На время операции отключается автосон существующих NVIDIA USB-устройств и меняется
общий параметр автосна для новых подключений, чтобы учесть переход Recovery → initrd.
Результат записывается в журнал; ошибки настройки видны. После операции возвращаются
исходный общий параметр и настройки сохранившихся исходных устройств. Новое USB-устройство,
появившееся в процессе, может сохранить отключённый автосон до переподключения.
Это не блокирует сон всего ноутбука: подключите зарядку и оставьте крышку открытой.

Физически плохой кабель программно не исправить. Используйте Micro-USB кабель данных,
прямой порт ПК и питание GEACX1. При медленной работе мастер продолжает ждать;
Таймауты самой передачи NVIDIA сохраняются. Ожидание появления USB-сети initrd
увеличено с 60 до 300 попыток проверки (время зависит также от ответа ping). Лимит 2 часа относится к скачиванию rootfs из
интернета, а не к прошивке. Автоматического повторного запуска записи после сбоя нет. Ctrl+C открывает запрос
STOP без остановки чтения журнала; одна лишь пауза перед ответом не блокирует прошивку.

## Что внутри

- Комплект **v1.4**: BSP производителя, NVIDIA Sample Root Filesystem R39.2.0, загрузчики,
  ядро, драйверы и русскоязычный мастер с backup/restore.
- **payload/** — данные полного архива. Скрипт собирает их автоматически: вручную
  переименовывать или объединять файлы не нужно.
- **manufacturer-extra/** — дополнительные исходные пакеты производителя. После
  подготовки их исходные DEB-файлы также будут в `~/geacx1-kit-v1.4/manufacturer-extra/`.
  Пакеты JP6.0, JP4.4/NX и CPLD сохранены для полноты исходников и **не устанавливаются
  сценарием JP7.2**. Не устанавливайте пакеты от другой версии JetPack поверх JP7.2.
- **docs/** — инструкция с картинками, оригинальное руководство и
  [отчёт о проверке сайтов производителя](docs/SITE_REVIEW_RU.txt).
- **recovery/** и **ci/** — исходники и тесты для проверки на GitHub. Пользовательский
  запуск выполняется через **START.sh в корне проекта**.

CUDA, cuDNN, TensorRT и полный пакет nvidia-jetpack устанавливаются после успешной
загрузки платы с проверкой совместимости. Они не входят в базовый образ восстановления.

В меню мастера **5 → 4** открывается краткая справка по материалам производителя,
а **5 → 1** показывает путь к актуальному руководству из комплекта. При вспомогательной
сетевой загрузке NVIDIA rootfs мастер показывает скорость и расчётное время и
останавливает загрузку, если общий прогноз превышает два часа. После восстановления
`POSTCHECK.sh` проверяет `fstab` и UUID через `findmnt --verify --verbose`, но ничего
в системе автоматически не исправляет.

Логи мастера по умолчанию: `~/geacx1-kit-v1.4/geacx1-recovery/logs/`.
Отчёт распаковки: `~/geacx1-kit-v1.4/unpack-verification.log`.

## Что выяснилось при проверке сайтов производителя

В списке производителя найден отдельный заводской
`rootfs_jp7.2_ga-orin-release_v1.01.tar.gz` размером **16,67 ГБ**. Это другой
файл: текущий комплект использует NVIDIA Sample Root Filesystem R39.2.0 вместе
с BSP, board, kernel и сервисами производителя. Заводской rootfs не скачан
полностью, его MD5 и содержимое не проверены, поэтому он не включён в v1.4.

На 2 октября 2026 года конфигурация `GEACX1-JP7.2.json` универсального сетевого
установщика отвечает HTTP 404. Пакеты JP4/JP5/JP6, NX, GEACX1SC и других ревизий
не используются вместо компонентов GEACX1 JP7.2. Найденный MCU-архив оказался
тестом GPIO/SPI, а не прошивкой. CPLD автоматически не прошивается: совместимость
старых v1.1/v1.3 с локальным rb v1.4 не доказана, а инструкция смешивает чтение
состояния с командами изменения режима.

## Отличие от заводского rootfs

Текущий образ собирается из официального NVIDIA Sample Root Filesystem R39.2.0,
BSP производителя, ядра и модулей GEACX1, конфигурации платы и сервиса вентилятора.
Заводской архив v1.01 может включать похожую основу и дополнительные пакеты/настройки.
Без его полного скачивания и сравнения нельзя утверждать, что системы одинаковы.
Разный размер или формат архивов не доказывает различия их распакованного содержимого.
Мастер принимает только проверенный архив NVIDIA; произвольный vendor rootfs подставлять нельзя.

## Проверки

[GitHub Actions](https://github.com/tehblok/geacx1-recovery-validation/actions/workflows/validate.yml)
проверяет тесты мастера и его основы, 8 тестов доставки, 10 аварийных сценариев
backup/restore, установку зависимостей в чистой Ubuntu 24.04 x86_64 и запуск
восьми утилит NVIDIA. Дополнительно полностью распаковывается поставляемый архив:
проверяются SHA-256, символические ссылки, совпадение кода и документов с проектом,
запуск мастера и вывод команд всех трёх режимов без обращения к плате.

Физическая прошивка, чтение и восстановление накопителей и загрузка этой платы
на GitHub не выполняются. Журналы CI сохраняются как artifact `geacx1-ubuntu24-evidence`.

SHA-256 и ожидаемый размер полного архива v1.4 хранятся в `parts.json` и
проверяются корневым `START.sh` перед распаковкой.

Файлы NVIDIA и производителя сохраняют исходные лицензии и уведомления.
